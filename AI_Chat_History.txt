================================================================
## Core Simulation Techniques
================================================================

----------------------------------------------------------------
### 1. Verlet Integration — Easy
----------------------------------------------------------------
The foundation of almost all rope/chain physics. Instead of tracking
velocity explicitly, you store the previous position and derive velocity
implicitly:

    new_pos = curr_pos + (curr_pos - prev_pos) * damping + acceleration * dt²

This is very numerically stable and naturally handles constraint solving.
Rain World uses this. Research: "Verlet integration game physics",
Thomas Jakobsen's classic GDC paper "Advanced Character Physics" (2001)
— free online, extremely relevant.


----------------------------------------------------------------
### 2. Distance Constraints (Constraint Relaxation) — Easy
----------------------------------------------------------------
Each pair of adjacent chain segments tries to maintain a fixed distance.
You iteratively "relax" them:

    delta = seg[i].pos - seg[i-1].pos
    correction = delta * (1 - rest_length / |delta|) * 0.5

Run this loop 3–10 times per frame for stability. This alone gives you
a basic tail. Research: "position-based distance constraints",
"Jakobsen constraints".


----------------------------------------------------------------
### 3. ECS Representation of a Chain — Easy-Medium
----------------------------------------------------------------
The key design question for your engine. Two approaches:
- One entity per segment with a ChainLinkComponent holding parent
  EntityId and rest length — fits your existing ECS well but adds overhead
- One entity with a ChainComponent holding a std::vector of segment
  positions — simpler, better cache behavior, harder to query per-segment
  for collision

Given your existing EntityId/generation system, the second approach
(one entity, array of points) is probably cleaner for a tail that
doesn't need individual entity logic.


----------------------------------------------------------------
### 4. Chain System as a New ECS System — Medium
----------------------------------------------------------------
You'd write a ChainSystem alongside your KinematicsSystem. It needs to:
- Read the root anchor (the player's body position)
- Apply Verlet integration to each link
- Solve distance constraints
- Write back positions for rendering

The tricky part: the root is kinematically driven (follows the player),
but the rest is physically simulated. You pin the first segment to the
player each frame after integration.


----------------------------------------------------------------
### 5. Angular Constraints — Medium
----------------------------------------------------------------
Distance constraints alone make the tail feel like a loose noodle.
Angular constraints limit how much adjacent segments can bend:

    angle between seg[i-1]→seg[i] and seg[i]→seg[i+1] < max_angle

Rain World uses this subtly to give the slugcat's body a more vertebrate
feel — it doesn't bend backwards sharply. Research: "angular constraints
Verlet", "bend constraints position-based dynamics".


----------------------------------------------------------------
### 6. Rendering the Chain — Medium
----------------------------------------------------------------
Options for drawing:
- Circles at each segment position (simplest, looks okay)
- Capsules between consecutive segments (more polished)
- Textured quads stretched between segments (sprite-based, Rain World style)

Your engine uses raylib, which has DrawLineBezier, DrawCircle, and raw
polygon drawing. The challenge is computing orientation per-segment to
align sprites. Research: "procedural rope rendering 2D".


----------------------------------------------------------------
### 7. Collision with Environment — Hard
----------------------------------------------------------------
Making the tail interact with platforms and walls is significantly more
complex:
- Each segment is a circle → use your existing CircleCollider type
- After constraint solving, push segments out of colliders
- Problem: this can cause constraint violations → need multiple solve
  passes interleaved with collision response
- The order of operations (integrate → collide → constrain vs.
  integrate → constrain → collide) matters a lot for stability

This is essentially the hard part of Rain World's system. Research:
"Verlet rope collision", "position-based dynamics collision response".


----------------------------------------------------------------
### 8. Inverse Kinematics (FABRIK) — Hard
----------------------------------------------------------------
Rain World uses this for limb placement (where feet land), not directly
for the tail. FABRIK is a forward-backward chain IK solver that's very
fast and stable. Only relevant if you want the tail to actively reach
toward or grab things. For a passive trailing tail, you don't need this.
Research: "FABRIK algorithm", "Aristidou FABRIK paper".

================================================================
## Recommended Starting Point
================================================================

Read Thomas Jakobsen's "Advanced Character Physics" (2001, IO Interactive
GDC paper). It covers Verlet + distance constraints in exactly the context
of character body simulation, and it's the direct ancestor of what Rain
World does. It's short, clear, and implementable in a weekend for the
basic version.

The version without environment collision (pinned root + Verlet +
distance constraints) is very doable for a 6-point engine task.
Environment collision roughly doubles the difficulty.
